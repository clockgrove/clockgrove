# Raccoon World observation

Run `pnpm dev:yard` from the repository root for the local living-yard checkpoint ([development runbook](../../docs/runbooks/development.md#local-living-yard-checkpoint)). It serves this app from Vite with the composed runtime on the same origin and prints the world route and the sign-in credential. `pnpm --filter @clockgrove/web dev` serves the app alone, against a runtime you compose yourself. The React/Vite entrypoint is the Raccoon World shell. Enter a local session credential and choose **Sign in**. The credential passes through the provider-neutral `BrowserAuthenticationPort` (`src/api.ts`) and is verified only by the runtime, through the world-directory read (`POST /v1/runtime/world-directory` with a bearer header), once per sign-in. A refused credential shows **Sign-in refused.** and no world data. The directory lists the scopes where the signed-in principal holds `runtime:world-observe`; the HUD's **World** selector lists them by world and space label.

A world route is the URL path `/worlds/{tenant}/{world}/{timeline}/{space}` (each identifier URL-encoded). It is shareable and carries no credential. Opening a route and signing in observes that world directly when the directory lists it; a route the directory does not list, or any other path except `/`, shows **World not available.** and no scene. Choosing a world in the selector pushes its route without a page reload and replaces observation; browser back and forward restore the route's world. The directory query belongs to the session's TanStack `QueryClient`; the route choice is transient Zustand state. The same observation grant authorizes public entity selection and recorded Why. Operator inspection requires the independent `runtime:world-inspect` grant, which does not grant observation. The observer authenticates each scene WebSocket upgrade at `/v1/projection` using the dedicated bearer subprotocol carrier; it requires no mutation grant and submits no canonical command.

Arrival is driven by one transient `WorldBootState` (`src/world-boot.ts`, held in the Zustand `useWorldBoot` store). Every value the shell holds is checked with `decodeWorldBootState`. A second status line announces the current state in text, and it is the only arrival progress: no spinner exists, and the observation status stays empty while it would read connecting or ready during arrival. Boot stays at `route_resolving` until the directory read has accepted the credential and lists the routed or selected scope. A signed-out browser, a browser opened at `/` with the selector shown, and an unlisted route all hold there. Then the boot moves through `identity_resolved` and `membership_authorized`, and reaches `joining_space` when the session opens the one scene socket, which happens only after the previous observation has retired. It reaches `snapshot_ready` once the first committed projection is published and `critical_assets_ready` once the renderer module loads and its reviewed atlas is ready. It reaches `scene_ready` after the adapter's `loadSnapshot` call for a committed revision returns. If the renderer module or its WebGL context fails, the boot ends at `text_ready` with reason `renderer_unavailable`, or the canvas is replaced by the text path once boot is already terminal; if the reviewed atlas fails to load or presentation fails, it ends there with `assets_unavailable`. Either way the semantic scene stays fully usable. Both ready states are terminal. Reconnection of a ready scene does not reset boot. A route change, a selector switch or a new sign-in starts a new boot at `route_resolving`; a switch reuses the cached directory query. Sign-in, not-available, refusal and unavailable screens are shell states outside `WorldBootState`.

The scene shows canonical revision, canonical simulation time, rain intensity and public entities. Snapshots and contiguous committed patches update the scene without a page reload. Entity buttons support keyboard selection, expose the same identities and positions as canvas picking and are listed in the canvas's pick order, so a committed move that changes the pick order also reorders the list and its Tab order. Canvas picks and entity buttons write the one shared selection, an object id held in the Zustand `useYardView` store. The isometric canvas ([scene contract](docs/scene.md)) labels only the selected entity, in bold with a sage selection ring, and the hovered one. Pointer hover over a canvas entity draws a thin white ring inside it, and keyboard focus on an entity button draws a thin blue ring outside it; both are lighter than the selection ring and separate from it. The **Entity rail** region shows the selected entity's name (its scene label from the entity-selection read, or its object id until that read returns), its public state (lifecycle and selected action) and its location, followed by the full selection panel. **Collapse entity rail** and **Open entity rail** toggle separate Zustand view state (`useEntityRail`) and never change the selection; scope changes, sign-out and authorization loss still clear it. The rail and the emphasis show only while a compatible committed scene is shown. The **Places** navigation lists the scene's visible hierarchy, the authority space and its declared nested regions, and shows the viewed place. **View** asks the runtime (`/v1/runtime/viewed-space`) to authorize that place with the current selection; its status message reports `followed`, `stayed_within_space`, `permission_denied`, `target_hidden` or `unavailable`, and a refusal clears the selection; a transport or server failure keeps the selection and says the request failed. Viewing a nested region changes only the **Viewing** label and the pressed place: the projection, entity list and canvas stay the whole authority space's, with no per-region filtering or camera move. Viewing commits nothing and keeps the one scene socket. The semantic scene and live status remain usable when canvas presentation is unavailable. An entity without a presentation binding draws as a placeholder marker. Sign-out, world changes and authorization loss clear observation and selection; authorization loss also signs out. Browser memory holds only replaceable projections and transient view state; PostgreSQL remains canonical.

The text path is a complete projection on its own (§11.2), usable with no canvas or WebGL. The **Living scene** gives a space summary (world, space, viewed place, weather in words and the number of perceivable entities) and lists every entity with its identity, pose and interactions (its interaction mode and the actions the server permits); lifecycle and current action are read for the selected entity in the Entity rail. Arrow keys, Home and End move focus between entity buttons, and Enter selects. The **Live changes** log announces actor movement, arrivals, departures, weather and new material events politely; it and the observation status update at most once every 3 s (`ANNOUNCE_INTERVAL_MS` in `src/text-scene.tsx`). This is a decision: the observation status still re-reads revision, time, rain and every entity position, but only at that bound, so it can lag the scene by up to 3 s. The timeline's event line is not a live region; stepping announces the event the user stepped to. The **Timeline** shows the timeline id, canonical revision and time, clock state and speed, and a branch placeholder (branching is Wave 7). **Earlier event** and **Later event** step through the recent material events, with **Open history of …** (which focuses the entity's recent authorized actions) and **Why event …**. When a focused control is rebuilt, for example across a reconnect, focus returns to the control with the same key (`src/focus.ts`). Under `prefers-reduced-motion` nothing animates, and the shell reflows at 320 CSS px with text at 200%.

Phaser is confined to the canvas adapter. The shell drives it only through the plan §9.1 `WorldSceneAdapter` (`loadSnapshot` with each committed projection, `setSelection`, `focus`, `setReducedMotion`, `onIntent`, `destroy`); [docs/scene.md](docs/scene.md) is the scene contract and its budgets. Pointer hover is picked and drawn by the renderer itself. The renderer-neutral contract also has a headless 3D consumer, the test fixture `test/headless-3d-adapter.ts`: it groups semantic object nodes by spatial frame at frame-local x, y and z, consumes committed snapshots and patches, presentation bindings and selection and focus and emits selection intents without Phaser or quadtree identity. TanStack Query owns committed projection, entity and Why server state; Zustand owns transient selection. The pure convergence reducer commits before publication to Query. The observer holds one scene socket and acknowledges only compatible committed endpoints delivered on the applicable resume version. Detected gaps show **degraded**, buffer bounded out-of-order patches and request backfill using resume on the current socket; snapshot requests send a null cursor hint. A backfill the outstanding one covers is not re-requested, and each committed revision restarts the outstanding request's 30 s lifetime (`SCENE_RECOVERY.requestTimeoutMs`); an expired backfill escalates to a snapshot request, and an expired snapshot request to a `SCENE_RECONNECT` reconnect. Runtime history and outstanding-frame limits still apply. Transport loss retains jittered bounded `SCENE_RECONNECT` backoff, showing degraded, connecting and then ready. Socket retirement completes before replacement activates. Session and connection lifetimes fence late results, errors and cleanup. Refusal, incompatibility and unrecoverable lag clear the live scene; authorization refusal displays unavailable with an authorization explanation and retires dependent selection and Why. Retry explicitly with **Retry observation**, or sign in again after authorization loss.

A `SceneCompatibilityError` from a snapshot, patch or control message never leaves a mismatched scene live: the committed projection, selection and Why are discarded at once, and boot does not advance for that projection, so it reaches neither `snapshot_ready`, `text_ready` nor `scene_ready` from it. `unsupported_protocol_version` and `unsupported_projection_version` show **degraded** and request a fresh snapshot on the current socket up to `SCENE_SNAPSHOT_RETRY.attempts` (2) times, one second apart (`src/projection.ts` records this decision). A compatible snapshot restores the scene and the retry budget. The next mismatch retires the socket and shows a stable **Unsupported scene protocol version** or **Unsupported projection version** screen, with no further retry. `unsupported_client_version` and `unsupported_asset_manifest_version` are not retried: the socket retires and an **Unsupported client version** or **Unsupported asset-manifest version** screen offers **Refresh**, which reloads the current deployment at the same route. Each screen (`src/recovery.tsx`) takes focus, announces its explanation in an alert and names the incompatibility, and the observation status reads `unsupported … version`. These screens are shell states outside `WorldBootState`, and the arrival announcement stays empty while one is shown. Text fallback (`text_ready`) is only for a compatible projection whose renderer or assets are unavailable. Credentials never enter the URL, cookies or web storage; the server negotiates only `clockgrove.scene.v1`, without echoing the credential.

Select an entity, then activate **Why action** beside a recent action to fetch its recorded command evidence from `/v1/runtime/why`. Tab and Enter or Space cover the complete scene, selection and Why path without canvas use. Opening Why focuses its heading; **Close Why** returns focus to its action button. The semantic panel exposes the original receipt/action identities, retained draft index, input revision and time, candidate scores and features, selected action and authorized causal command links. These recorded values stay tied to the immutable receipt while the scene and derived current-time values change. No browser-generated explanation or canonical mutation is involved.

The Why panel can also start somewhere other than a command. Each event-feed item has one **Trace event** button per source event (an aggregated item has several), which opens Why from that event and shows the Why of the event's command. The Why panel sits in the main column, beside rather than inside the selection panel, so it serves every entry. Each scheduled action that Why lists has a **Trace scheduled action** button. The panel names where the traversal started and labels each part with its evidence class (`canonical` or `derived`). **Trace my view** opens the client-view trace: the audience the server decided for this view, its viewer reasons, whether its hash matches the frames the view receives, and the projection revision. That decision is labelled `transient`. The selected entity's panel labels its earned current-time values `derived`.

The entity rail's interaction card shows the server's mode disclosure and only the actions the server's policy returned for that entity. A disabled action shows its reason. **Why** opens the newest recorded routine decision. **Influence** offers one unit of a resource as a suggestion and shows the receipt's stages. **Talk** is a scripted fixture: private Caretaker talk stays in the card, and only **Say publicly** speaks in the public speech region.

Why distinguishes an empty recorded decision set from unavailable or redacted evidence. Refused access clears authorized observation; inspector rate limiting is announced as a refused request, and other unavailable reads can be retried by activating Why again. New action/entity selection (for a Why opened from an action; a Why opened from an event or scheduled action stays open when another entity is chosen and closes when the selection is cleared), history-page replacement, world change, sign-out and current authorization failure discard superseded Why results and errors. The [public observation contract](../../docs/protocols/living-yard-observation.md#recorded-why) defines the closed vocabulary and failure codes. Broader caller ceilings cannot reveal authority metadata, private cognition references or provider identities in this shared view.

The shell is a three-part layout (`.rw-shell`): a one-line HUD with the World selector and a centered world clock (simulated day, time, running or paused, speed, weather) from the authorized world-status read; the scene with the entity rail at its right fifth; and a material event feed at the lower left, built from authorized semantic events, where choosing an item selects its entity. Below 1200px the rail and feed become collapsed bottom sheets. Tokens are versioned `--rw-v1-` CSS variables in `src/raccoon-world.css`; see [the UI composition](../../docs/design/raccoon-world-ui.md).

No fixture or static image is presented as a world. The shell supplies no production credentials or authentication bypass.

The real finite Chromium/native runtime/PostgreSQL journey is in `tests/e2e/living-yard.journey.browser.test.mjs` (the browser-build CI share). It proves sign-in refusal, the directory's labels against PostgreSQL memberships, the not-available state of an unlisted route, direct route opening and selector switching. It compares native snapshot and committed patch revisions with PostgreSQL, checks committed content in Query and semantic text, and checks completed Phaser draw revisions, labels and isometric pointer picking, depth order, the fixed camera's zoom and pan bounds, rain and night from canonical state, touch cycling, reduced motion, interpolation and snapping, context-loss fallback and the runtime budgets on the golden yard with rain. It checks the drawn selection ring and label, the hover and focus rings, and the rail's name, public state and location for a birth-fixture entity across collapsing and reopening the rail, with the selection unchanged. It requires connecting → ready → degraded → connecting → ready through a real socket drop/resume. Authorization refusal removes authorized data and displays unavailable. Protocol, projection, asset-manifest and client compatibility rejection removes the live scene. Protocol and projection mismatches send exactly two snapshot retries on the same socket before their unsupported-version screen; asset-manifest and client mismatches show their screen at once, and **Refresh** reloads the page at the same route. No boot state follows a rejected snapshot. Observation and recovery leave canonical revision and command receipts unchanged. These are local Chromium checks, not hosted hibernation, deployment, participant evaluation or full Wave 4 qualification.

Browser-free route authorization, redaction and logging checks remain in `apps/runtime/test/living-yard.journey.postgres.test.ts`; the headless adapter and session-intent journey is in `apps/web/test/scene-adapter.journey.contract.test.ts`. `pnpm check` typechecks, enforces browser boundaries, builds through Vite and checks the build-time scene budgets (`tools/scene-budget.mjs`). The boundaries (`tools/web-boundaries.mjs`) confine Phaser to `src/renderer.ts`, which reaches the React shell only through `src/world-scene-adapter.ts`, a bridge that imports only `@clockgrove/contracts`; React, TanStack Query and Zustand stay in the shell; no client module imports runtime, persistence, application, testkit, trusted-contract, authentication-provider, model-provider or database packages. `scripts/check-boundaries.mjs` keeps React and Phaser out of `apps/runtime` and `packages/*`. Full qualification remains distinct from local checks.
